⛔Bloquant pour ta réinstallation : le clavier interne ne marche pas à la phrase LUKS

  • L'installateur 4.5 voit que linux-omarchy n'a pas le module t2bce_vhci. Il écrit alors zz-omarchy-kernel-modules.conf, qui retire ce module de tous les initramfs, y compris celui de linux-t2.
  • Confirmé sur MacBookPro16,1 (issues #17755 et #17155). Les correctifs (PR #18035, #17164) ne sont pas encore fusionnés.
  • Contournement : tape la phrase LUKS sur un clavier USB au premier démarrage. mbp16-1 setup (via apply gpu) répare ensuite toutes les images de démarrage, linux-t2-mbp161 comprise. Le clavier interne remarche au démarrage suivant.
  • La toolbox ne touche pas aux fichiers d'Omarchy : elle ajoute zzz-mbp16-1-t2bce.conf, lu après zz-omarchy-kernel-modules.conf. Le ? laisse linux-omarchy se construire sans t2bce. doctor vérifie le module dans les images.
# seul, sans le reste de setup (même fichier que apply gpu)
./bin/mbp16-1 apply luks
# à la main
printf '%s\n' 'MODULES+=(t2bce_vhci?)' | sudo tee /etc/mkinitcpio.conf.d/zzz-mbp16-1-t2bce.conf
sudo mkinitcpio -P && sudo limine-update

✎Correction du 08/11 : l'écran Intel

  • force_igd bascule la dalle sur l'Intel après que le firmware l'a allumée sur l'AMD. i915 la pilote alors sur 2 voies, 18 bpp avec tramage. Ça marche, mais ce n'est pas le mode natif (deqrocks, mainteneur de KaiT2en).
  • La piste est la variable NVRAM gpu-power-prefs = 1 : le firmware démarre sur l'Intel, i915 entraîne le lien lui-même. Test sans rien installer, un redémarrage : README C2b. doctor affiche la ligne « Boot GPU ».
  • t2linux PR #77 (4 voies forcées par quirk i915) n'est pas retenue : elle contourne force_igd au lieu d'en corriger la cause.

BComment Omarchy 4.5.0 s'installe sur un Mac T2 aujourd'hui

D'après le code de omacom/omarchy-iso et omacom/omarchy (branche quattro), et les retours d'utilisateurs de 16,1 dans #17755.

  1. 1
    Démarrage sur la clélive : linux-t2 7.2.11

    GRUB lit le SMBIOS. Si le fabricant est « Apple Inc. », il démarre le live sur linux-t2, que l'ISO embarque à côté de linux-omarchy. Dans le live, applesmc est désactivé.

    iso 256a0e4 (21/10) configs/grub/loopback.cfg · builder/build-iso.sh:365 · a12bfea · ed710a3
  2. 2
    Détection de la puce T2choix : linux-t2

    L'installateur trouve le PCI 106b:1801/1802 et choisit linux-t2 comme noyau par défaut.

    orchestrator context.py::_default_kernel
  3. 3
    Disque⚠Full disk install est listé en premier

    Choisis Free space install (alongside existing data). L'installateur crée OMARCHY_EFI, puis LUKS2 + btrfs dans l'espace libre. Le démarrage passe par Limine et des UKI.

  4. 4
    Copie du systèmelinux-omarchy 7.2.15 + linux-t2 7.2.11

    L'image de base contient linux-omarchy et ses headers. linux-t2-headers vient d'arch-mact2 : il faut le réseau.

  5. 5
    Scripts T2 d'Omarchy (chroot)config T2

    pacman.sh ajoute [arch-mact2] avec SigLevel = Never. fix-t2.sh installe linux-t2, ses headers, apple-t2-audio-config, apple-bcm-firmware-fetcher et t2fanrd. Il écrit aussi :

    modules-load.d/t2.conf (t2bce_vhci, hci_bcm4377) · mkinitcpio.conf.d/apple-t2.conf MODULES+=(t2bce_vhci usbhid hid_apple …) · ligne de noyau intel_iommu=on iommu=pt pm_async=off mem_sleep_default=deep · t2fand.conf (Fan1, Fan2 : 55→75 °C) · brcmfmac feature_disable=0x82000

    install/hardware/pacman.sh · install/hardware/apple/fix-t2.sh · fix-brcmfmac-supplicant.sh
  6. 6
    Construction des UKI : le bug✗t2bce_vhci retiré partout

    _drop_initramfs_modules_the_kernel_lacks() voit que linux-omarchy n'a pas t2bce_vhci. Il écrit zz-omarchy-kernel-modules.conf avec _omarchy_absent=(t2bce_vhci), et le module disparaît aussi de l'initramfs de linux-t2.

    phases_impl.py · issues #17155 (31/10), #17755 (05/11) · PR #17164, #18035 ouvertes
  7. 7
    Premier démarrageboot : linux-t2 7.2.11

    Limine suit BOOT_ORDER="linux-t2, linux-omarchy, linux-omarchy-*, *, *fallback, Snapshots". À la phrase LUKS, le clavier interne ne répond pas : utilise le clavier USB ; mbp16-1 setup fait ensuite la réparation.

    omarchy ff85faf (14/09) etc/limine-entry-tool.d/omarchy-defaults.conf
  8. 8
    Ouverture de session⚠#9609 toujours ouvert

    Sur 16,1, le gmux laisse l'écran sur l'AMD, ce qui peut bloquer la machine. Si l'écran reste noir : dans Limine, e, ajoute module_blacklist=amdgpu, puis F10.

  9. 9
    ta boîte à outilsmbp16-1 setupboot : linux-t2-mbp161

    Compile linux-t2-mbp161, met l'écran sur l'Intel (force_igd, 2 voies), répare le clavier LUKS, garde le Titan Ridge éveillé, passe la veille en s2idle et remplace le BOOT_ORDER. doctor doit afficher Limine default linux-t2-mbp161.

GDans l'ordre

  1. Prépare un clavier USB et un adaptateur USB-C. Enregistre la phrase LUKS et le mot de passe dans ton gestionnaire.
  2. Sur macOS : ./bin/mbp16-1 macos (supprime l'ancien Linux, exporte les empreintes, ISO 4.5.0, écrit la clé).
  3. ⌥ au démarrage → EFI Boot orange → Free space install (alongside existing data).
  4. Premier démarrage : phrase LUKS au clavier USB.
  5. ./bin/mbp16-1 setup (il inclut la réparation LUKS), puis doctor → Limine default linux-t2-mbp161 et t2bce_vhci in boot image. Redémarre au clavier interne pour le confirmer.
  6. uname -r se termine par -t2-mbp161, puis ./bin/mbp16-1 apply touchid.
  7. Test ★ gpu-power-prefs (README C2b) : un redémarrage, puis lane_count et bpp (pas boot_vga : force_igd le met à 1 dans tous les cas). Si 4 voies : palier 2 dans une PR séparée.
