# Optional A/B tests: microphone DSP, speaker DSP, Wi-Fi IPv6

None of this is part of `setup` or `doctor`. This toolbox has not tested any of it on this machine. Make one change at a time, and record the "before" numbers first: the microphone DSP hides the raw microphone once it is installed. Sources were reviewed on 2026-11-08 at the commits named below.

| Test | Change | Verdict before testing |
| --- | --- | --- |

| [2. Speakers](#2-speaker-dsp) | lemmyg / KaiT2en 16,1 speaker graph | Do not install yet. No clean package for this stack |
| [3. Wi-Fi](#3-wi-fi-ipv6-throughput) | IPv6 vs IPv4 throughput on BCM4364 | Measure first. The cause is known; the fix is a kernel patch |

## 1. Microphone DSP

[kazeshini178/t2-mbp16-1-mic-dsp-arch](https://github.com/kazeshini178/t2-mbp16-1-mic-dsp-arch) at `a62dfa3` (2026-09-21) provides two Arch packages:

- `triforce-lv2`: chadmed's LV2 beamformer, built from a pinned commit (`fba437e`) with checksums.
- `t2-mbp16-1-mic-dsp`: lemmyg's `16_1/mic.json` (Triforce, high-pass filter, gain) plus a WirePlumber rule. It exposes one mono source, **MacBook Pro T2 DSP Mic**, and hides the raw 3-channel source.

How it fits this stack:

- It depends on `apple-t2-audio-config`, which the Omarchy installer already installs on T2 Macs. It does not touch speakers or any file this toolbox writes.
- An install hook refuses anything that is not `MacBookPro16,1`. Pacman owns every file it installs.
- The pinned `mic.json` (lemmyg `7ad15c7`) is the same as lemmyg `master` (`1895a70`). Since then only the speaker FIR files have changed.
- Omarchy 4.5's speaker tunings match only `dell-xps-2026` and `asus-proart-p14-n1x`, so nothing there conflicts.
- Do not combine it with lemmyg's `install.sh` or with bentsignal's DSP: each renames the same microphone node.
- The author measured a speech peak of −42.2 dBFS raw and −26.4 dBFS through the DSP (+15.8 dB). Gain alone would raise the noise as well, so the useful number below is the signal-to-noise gap.

### Before

`sox` (`sudo pacman -S --needed sox`) does the measurements. Record both clips at 30 cm, in the same room, reading the same text.

```bash
mkdir -p ~/ab/mic && cd ~/ab/mic
RAW=$(pactl list short sources | awk '$2 ~ /HiFi__Mic__source$/ {print $2; exit}'); echo "$RAW"
timeout -s INT 10 pw-record --target "$RAW" --rate 48000 --channels 1 before-speech.wav   # read aloud
timeout -s INT 10 pw-record --target "$RAW" --rate 48000 --channels 1 before-silence.wav  # stay quiet
for f in before-*.wav; do echo "$f"; sox "$f" -n stats 2>&1 | grep -E 'Pk lev dB|RMS lev dB'; done
```

### Install

```bash
mkdir -p ~/code/oss && cd ~/code/oss
git clone https://github.com/kazeshini178/t2-mbp16-1-mic-dsp-arch.git
cd t2-mbp16-1-mic-dsp-arch
git checkout --detach a62dfa3a51cd9c88dc085de2fb347236648602e8   # the revision reviewed here
bash tests/test_packages.sh                                     # policy checks, needs rg
(cd triforce-lv2 && makepkg --syncdeps --rmdeps --cleanbuild --force)
(cd t2-mbp16-1-mic-dsp && makepkg --cleanbuild --force --nodeps)
sudo pacman -U \
  triforce-lv2/triforce-lv2-0.3.2.r0.gfba437e-1-x86_64.pkg.tar.zst \
  t2-mbp16-1-mic-dsp/t2-mbp16-1-mic-dsp-0.1.r0.g7ad15c7-1-x86_64.pkg.tar.zst
systemctl --user restart wireplumber pipewire pipewire-pulse
```

### After

```bash
cd ~/ab/mic
DSP=$(pactl list short sources | awk '$2 ~ /t2-161-mic/ {print $2; exit}'); echo "$DSP"
wpctl status | sed -n '/Sources:/,/Filters:/p'      # "MacBook Pro T2 DSP Mic" marked *; else wpctl set-default <id>
timeout -s INT 10 pw-record --target "$DSP" --rate 48000 --channels 1 after-speech.wav
timeout -s INT 10 pw-record --target "$DSP" --rate 48000 --channels 1 after-silence.wav
for f in *.wav; do echo "$f"; sox "$f" -n stats 2>&1 | grep -E 'Pk lev dB|RMS lev dB'; done
pw-play before-speech.wav; pw-play after-speech.wav  # listen with headphones
```

Keep the DSP microphone if all three hold:

- The speech peak is between −25 and −15 dBFS, and above −1 dBFS nowhere, so it does not clip.
- The SNR (speech RMS minus silence RMS) is larger after than before.
- It sounds at least as clear, and a call in your usual app works.

Apps that had the raw microphone selected need to be pointed at the new source. Chromium-based apps must be restarted to see it.

### Rollback

```bash
sudo pacman -R t2-mbp16-1-mic-dsp triforce-lv2
systemctl --user restart wireplumber pipewire pipewire-pulse
```

## 2. Speaker DSP

There are three 16,1 speaker graphs. None of them is a clean fit for this Omarchy stack today:

| Source | What it is | Why not now |
| --- | --- | --- |
| KaiT2en `t2bce_audio-dsp` (arch-mact2 tag `kait2en`) | Newest per-model graphs, generated by KaiT2en from lemmyg's | Its pacman dependency `t2bce_audio` is provided only by `t2bce-dkms`, which replaces linux-t2's in-tree t2bce stack, the stack that drives the keyboard at the LUKS prompt. Its UCM package `t2bce_audio-alsa-ucm-conf` replaces Omarchy's `apple-t2-audio-config`. It belongs to step 2 (stock linux-t2 + KaiT2en), and only as a separate step after it |
| [lemmyg/t2-apple-audio-dsp](https://github.com/lemmyg/t2-apple-audio-dsp) `configs/16_1` | bankstown bass, LSP compressor, loudness compensation, woofer/tweeter FIRs, 6 channels out. FIRs trimmed on 2026-10-01 | Ubuntu-oriented `install.sh`: no pacman owner, plus a udev rename rule. Its README now points to KaiT2en and keeps the repo "for reference" |
| [bentsignal/t2-omarchy](https://github.com/bentsignal/t2-omarchy) `files/graph.json` | lemmyg `b5c5a136` (2026-07-31) plus an swh lookahead limiter | Installs `bankstown` and `swh-lv2-git` (2020) from the AUR with `yay`, and symlinks into `/usr/share/wireplumber/scripts`, which a package owns |

lemmyg warns that misconfigured userspace settings can damage the speakers for good. Their README also asks for the raw speaker sink to be at **100 %**, with volume controlled on the DSP sink. That is safe only while the DSP is actually loaded. If the graph fails (a missing plugin, for example), the raw sink comes back at 100 %.

The clean path, if stock speakers bother you: package lemmyg's `16_1` speaker graph the way kazeshini178 packaged the microphone. That means a pinned commit, a pacman owner, an exact-model guard, and no change to UCM. It would be a separate PR. Until it exists:

- **Before:** pick two reference tracks (voice, bass-heavy music). Play them with `pw-play` at a fixed volume, 40 %, and note what you hear.
- **After** (once there is a package): same tracks, with the DSP sink at the volume that sounds equally loud. Louder always sounds "better", so match loudness by ear first. Then check that the Omarchy volume keys move the DSP sink, not the raw one: `wpctl status` before and after pressing them.

## 3. Wi-Fi IPv6 throughput

### What is known

- On the **same model and chip** (MacBookPro16,1, BCM4364), bentsignal [measured](https://github.com/bentsignal/t2-omarchy/blob/main/docs/wifi-performance.md) 54–58 Mbit/s over IPv6 against 295 Mbit/s over IPv4 on the same M-Lab server, then about 500 Mbit/s once IPv6 was off on that profile. Their workaround is `ipv6.method disabled` on that one Wi-Fi profile. Turning power save off alone did not help.
- deqrocks found the cause (KaiT2en [`0014`](https://github.com/kaiT2en/KaiT2en-Fedora/blob/main/patches/runtime/wireless/0014-wifi-brcmfmac-keep-ARP-and-ND-offload-off-on-the-BCM4364-while-awake.patch), also submitted upstream). brcmfmac enables the firmware's ARP and IPv6 ND offload whenever the interface is up. On Apple's BCM4364 firmware, ND offload caps IPv6 downloads at about 55 Mbit/s. macOS enables these offloads only in sleep.
  - The patch keeps them off while the Mac is awake.
  - It is patch `04` in the 7.2.15 kernel prepared on 2026-11-08.
  - Stock `linux-t2` 7.2.11 does not have it. The earlier `linux-t2-mbp161` 7.2.3 did not either.
- Power save is already off by default: Omarchy 4.5 ships `/etc/NetworkManager/conf.d/omarchy-wifi-powersave.conf` with `wifi.powersave = 2`. Only a profile that explicitly says `3 (enable)` overrides it.
- `feature_disable=0x82000` (D2) concerns the WPA handshake, not throughput. The Omarchy 4.5 installer already writes the identical `/etc/modprobe.d/brcmfmac.conf`; `apply wifi` re-asserts it.
- **Never disable IPv6 system-wide** (sysctl `disable_ipv6`). Touch ID reaches BridgeOS over link-local addresses on the T2 NCM interface. A per-profile setting on the Wi-Fi connection does not affect it.

### Measure

```bash
IF=$(nmcli -t -f DEVICE,TYPE device | awk -F: '$2=="wifi" {print $1; exit}')
CON=$(nmcli -g GENERAL.CONNECTION device show "$IF"); echo "$IF / $CON"
iw dev "$IF" get power_save
nmcli -f 802-11-wireless.powersave,ipv6.method connection show "$CON"
iw dev "$IF" link | grep -E 'freq|signal|bitrate'
ip -6 route show default                             # empty: no IPv6 on this network, stop here

# Same dual-stack server for both families, 15 s each, alternated 3 times
URL=https://geo.mirror.pkgbuild.com/iso/latest/archlinux-x86_64.iso
for i in 1 2 3; do for f in 4 6; do
  printf 'IPv%s ' "$f"
  curl -"$f" -s -o /dev/null --max-time 15 -w '%{speed_download}\n' "$URL" | awk '{printf "%.0f Mbit/s\n", $1*8/1e6}'
done; done
ping -4 -c 20 -i 0.2 1.1.1.1 | tail -1
ping -6 -c 20 -i 0.2 2606:4700:4700::1111 | tail -1
```

If IPv6 is within about 20 % of IPv4, there is nothing to fix. If IPv6 sits near 50–60 Mbit/s while IPv4 is far higher, ND offload is the suspect.

### Confirm the cause without a new kernel

brcmfmac turns ARP/ND offload off whenever the interface is promiscuous (`brcmf_configure_arp_nd_offload(ifp, !promisc)` in `core.c`, checked in the 7.2.15 source). `tcpdump` does the same by default. This is a **temporary diagnostic**: promiscuous mode makes the firmware pass more frames to the host. Turn it off before suspending.

```bash
sudo ip link set dev "$IF" promisc on
ip -d link show dev "$IF" | grep -o 'promiscuity [0-9]*'   # 1
# rerun the curl loop above: IPv6 should now match IPv4
sudo ip link set dev "$IF" promisc off
```

### Fix, in order of preference

1. **Kernel with `0014`** (the prepared 7.2.15, or step 2 if KaiT2en carries it). This keeps IPv6. Rerun the measurement after the first boot.
2. **Meanwhile, per profile** (bentsignal's workaround). IPv6-only destinations become unreachable on that network:
   ```bash
   nmcli connection modify "$CON" ipv6.method disabled
   nmcli connection up "$CON"
   # rollback
   nmcli connection modify "$CON" ipv6.method auto && nmcli device reapply "$IF"
   ```
   The setting lives in the saved profile only. A new network, or a deleted and re-created profile, starts with IPv6 again.
3. **Power save**, only if the profile showed `3 (enable)`. Setting it to `0` makes the profile follow Omarchy's global `2`:
   ```bash
   nmcli connection modify "$CON" 802-11-wireless.powersave 0
   nmcli connection up "$CON"
   iw dev "$IF" get power_save                                  # off
   ```
